## 第一遍·AI味

- [第1段第1句] "随着AI技术的发展，开源社区又迎来一款新工具。" → 这是write-article反例清单里明确点名的套路开头，一字不差。删掉，直接从具体事实切入，比如"上周，某团队开源了一个叫CodeWeave的代码助手"。
- [第1段第2句] "上周，某团队开源了一个叫CodeWeave的代码助手[^1]，官方文档里的定义是"一个把审查、测试、部署整合进单一界面的平台"：这不是一个简单的IDE插件，是一整套围绕AI协作重新设计的工作流，说明团队显然是想抓住开发者工具这一轮的新机会。" → 一句话里塞了"开源了什么+引用官方定义+'A不是B是C'对照判断+'说明……显然'结论"四件事，逐字数下来这一句约116字，是30字上限的近4倍。拆成3-4句：①团队开源了什么，单独成句；②官方定义单独引用成句；③如果要下"不是IDE插件"这类判断，单独成句，且不要顺带把"说明团队显然是想抓住机会"这种结论硬缝进同一句——判断要么单独成句要么直接删掉。
- [第2段第1句] "这套工具的核心不是替代人写代码，而是辅助人做决策——不是让AI全自动完成任务，是让AI给出建议、人来拍板。" → 一句话里堆了两次"不是A是/而是B"，中间用破折号硬连，读起来是同一个意思说了两遍。拆开、只留信息量更大的一句，比如"这套工具的核心不是替代人写代码，而是辅助人做决策：AI给建议，人拍板。"
- [全文] grep数了"不是"出现的次数：4次——"这不是一个简单的IDE插件"（第1段）、"核心不是替代人写代码"（第2段）、"不是让AI全自动完成任务"（第2段）、"而不是"人放权""（第2段，"而不是"里也含"不是"）。短短4段文章里"A不是B"变体出现4次，已经是"超过3-4次形成可辨认AI腔节奏"的量级。保留1处判断力最强的（比如"不是替代人写代码，而是辅助人做决策"），其余改成正面表述，比如"不是让AI全自动完成任务，是让AI给出建议、人来拍板"→"AI负责给建议，人负责拍板"。
- [第2段第2句] "这种设计思路——某种程度上——跟目前流行的agent框架不太一样——它更强调"人在回路"，而不是"人放权"。" → 一句话里塞了三个破折号，"某种程度上"是典型的态度模糊限定词。改成"这种设计思路跟目前流行的agent框架不太一样：它更强调'人在回路'，而不是'人放权'。"，去掉"某种程度上"，破折号只留一处做转折。
- [全文] grep数了破折号"——"出现的次数：5处——第2段"……决策——不是……"1处，第2段"……思路——某种程度上——……不太一样——它更强调……"这一句里连用3处，第4段"……好坏——这里说清楚……"1处。远超"1-2处以内"的标准，尤其第2段第2句一句话里就占了3处，读起来像说话打磕巴，需要逐处改成正常的逗号/句号或冒号。
- [第3段第1句] "CodeWeave的插件生态支持约50家服务商，赋能整个开发链路，形成从写代码到发布的完整闭环。" → "赋能""链路""闭环"三个书面AI热词堆在一句话里（清单第10类此前一直是占位没有真实案例，这篇撞上了）。改成具体说法，比如"CodeWeave的插件生态接了大约50家服务商，从写代码、测试到发布基本都能接得上。"，不用"赋能/链路/闭环"这类空词。
- [第3段第2句] "这不仅是一次工具升级，更是对整个研发流程的重新定义。" → 典型"不仅是……更是……"排比升华句，且"重新定义"具体指什么没说，内容空泛。删掉，或者换成具体判断，比如指出这次整合到底改变了哪个环节的工作方式。
- [第3段第3句] "一方面，这种整合确实能提高效率；另一方面，也有人担心这会让新手过度依赖AI判断，丧失独立解决问题的能力。" → "一方面……另一方面……"和稀泥，两边都不下判断（清单第11类此前也是占位没有真实案例，这篇撞上了），跟write-article"结尾给判断不给总结"的声音要求正相反。挑一边站队，比如"我更担心后一种——效率提升看得见，但独立解决问题的能力会不会被悄悄替换掉，等实际用过再看。"
- [第4段第1句] "我还没有实际用过这款工具，没测过它的真实性能，不好直接评价好坏——这里说清楚，我目前的判断基于官方文档和几篇评测文章，还没有一手体验。" → "没用过/没测过/不好评价"和后面"这里说清楚……还没有一手体验"说的是同一件事，重复了两遍，中间还用破折号硬连。只保留一句，比如"我还没实际用过这款工具，这里的判断基于官方文档和几篇评测文章，不是一手体验。"
- [第4段最后两句] "总的来说，CodeWeave代表了开发者工具的一个新方向。它的出现，也提醒我们，AI辅助编程这个赛道还远没有定型。" → "总的来说"起头的空泛总结，"代表了新方向""还远没有定型"都是正确但没有信息量的话，任何一个技术公众号结尾都能这么写，没有下具体判断。换成实打实的判断句，比如"CodeWeave值不值得现在上手，我倾向于再等等——'人在回路'的思路是对的，但生态和实际体验都还没验证过。"
- [全文结构] 四段几乎都是"事实/描述+总结拔高句"的固定节奏——第1段收在"说明团队显然是想抓住机会"，第3段收在"这不仅是……更是……"，第4段收在"总的来说……"，读起来像模板化的机械三段式。至少砍掉2-3处这种总结尾巴，让事实本身说话，只在真正有判断力的地方才收一句判断。

## 第二遍·细节

- [标题] 全文没有标题（没有单独的标题行）→ 无法判断是否有吸引力、是否符合topic-gen的标题公式，需要先补一个标题，建议围绕"人在回路 vs 全自动"这个文章里真正的判断点来拟，而不是"XX工具开源了"这类泛泛标题。
- [开头三句话] 已在第一遍第1条标记为套路开头，从"能不能留住读者"这个角度看同样成立——"随着AI技术的发展"这类通用开头读者扫一眼就知道是模板文，留不住人。同一处，改法见第一遍第1条。
- [第1段第2句] 逐字数下来这一句约116字（"上周，某团队开源了……这一轮的新机会。"整句只靠一个冒号断句，没有句号），是全文最长的一句，远超30字上限的近4倍。已在第一遍第2条给出拆句方案，这里从纯长度角度确认：至少要拆成3-4句才够。
- [第2段两句、第3段第1/3句、第4段第1句] 全文大部分句子都在40-60字以上，只有第3段第2句（"这不仅是一次工具升级，更是对整个研发流程的重新定义。"约24字）勉强达标。30字是上限不是常态，需要逐句检查，能拆的都拆。
- [第1段] 单段把"开源了什么+官方定义+性质判断+意图判断"四件事挤在一段里没有分段，手机上读是连续一整块。从"官方文档里的定义是"处断开，定义单独成段或至少单独成句后空一行。
- [脚注1] "[^1]: CodeWeave官方GitHub仓库，2026年8月发布。"只写了"GitHub仓库"字样，没有给出实际URL链接。这篇是GitHub项目类文章，硬约束要求给仓库链接，需要补上真实的repo地址（比如`https://github.com/xxx/CodeWeave`）。
- [第4段最后两句] "总的来说，CodeWeave代表了开发者工具的一个新方向。它的出现，也提醒我们，AI辅助编程这个赛道还远没有定型。"是可以整段删掉的冗余总结，删掉后信息量不减反而更利落；或者按第一遍最后一条的建议换成具体判断句。
