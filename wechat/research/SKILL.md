# 公众号深度调研

## 这个 skill 做什么

针对已经选定的选题方向，做信息搜集，边搜边把结果存进文件，最后整理成一份结构化简报。不写文章正文，只产出调研素材。

## 执行步骤

### 1. 确认调研范围

如果选题方向、核心角度还不清楚，先跟用户确认要调研的具体问题是什么——不是泛泛地"了解一下这个话题"，而是"这篇文章需要哪几个具体问题的答案"。范围越具体，调研效率越高。

### 2. 按信息源优先级搜索

搜索顺序：

1. 官方信息源——官方博客、官方文档、官方公告
2. 一手报道——权威科技媒体、行业媒体
3. 社区讨论——社交媒体、论坛、评论区，用来补充官方信息里没有的真实反馈和争议点

同一个事实尽量找到至少2个独立信息源交叉验证。忽略过时或低质量信源——年代久远的问答帖、明显的营销软文、找不到原始出处的二手转述，这类信息不进简报，不用为了凑数据点降低标准。

### 3. 边搜边存，不要等全部搜完再保存

**具体到执行动作上：每发出一批 WebSearch/WebFetch 工具调用、拿到结果，在发下一批调用之前，先把这批结果追加写入调研文件。** 不是"搜完一整类信息源"才算一批——一次并行发好几个搜索/抓取调用本身就是一批，跑完就该落盘，不要连续发好几轮调用、心里记着结果、最后一次性把所有发现汇总成简报再写文件。后者等于会话中断时前面全白搜，也是"边搜边存"这条原则实际失效的最常见方式。每完成3轮搜索，额外存一次"阶段摘要"（当前已确认的关键发现，几句话即可），方便调研中途被打断时快速看出进度到哪了。

调研文件建议路径：`research/{选题slug}.md`。

### 4. 汇总成结构化简报

调研文件最终要整理成这个结构：

```
# {选题} 调研简报

## 关键事实
- 事实1（信息源：链接，可信度：高）
- 事实2（信息源：链接，可信度：中，单一信息源未交叉验证）

## 信息源列表
| 来源 | 链接 | 类型 | 可信度 |
|------|------|------|--------|
| ... | ... | 官方/一手报道/社区讨论 | 高/中/低 |

## 待确认问题 / 争议点
- ...
```

可信度分三档：官方信源、或2个以上独立信源交叉验证 → 高；单一权威信源（一手报道、官方但未交叉验证）→ 中；社区讨论、未交叉验证的二手转述 → 低。低可信度的事实可以放进简报，但要在"待确认问题"里再提一遍，别让它悄悄混进"关键事实"被当成定论。

### 5. 汇报调研覆盖情况

调研完成后告诉用户：覆盖了哪几类信息源、哪些问题还没找到明确答案、要不要继续深挖某个点。不要默认调研已经"足够"，让用户判断是否可以进入写作。

## 参考示例

```
# GLM-5V-Turbo发布 调研简报

## 关键事实
- 支持128k上下文（信息源：官方博客 https://...，可信度：高）
- 定价较上一代下降40%（信息源：官方公告 https://...，可信度：中，单一信息源未交叉验证）

## 信息源列表
| 来源 | 链接 | 类型 | 可信度 |
|------|------|------|--------|
| 官方博客 | https://... | 官方 | 高 |
| 科技媒体报道 | https://... | 一手报道 | 中 |

## 待确认问题 / 争议点
- 是否支持流式多模态输入，官方文档表述模糊，实测前无法确认
```

## 边界

- 不写文章正文，只产出调研素材文件。
- 每条关键事实必须标注可信度（高/中/低），不能当作已验证的定论笼统呈现。
- 找不到足够信息时，在简报里如实写"信息不足"，不要编造内容填充。
