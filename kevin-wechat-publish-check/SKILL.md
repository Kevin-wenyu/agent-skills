# 公众号发布前检查

## 这个 skill 做什么

对已经审校、配图完成的文章做最后一遍发布前检查，产出发布就绪的文本和检查清单。不涉及实际发布操作。

## 执行步骤

### 1. 元信息检查

- 标题：字数是否在公众号标题显示的合理范围内，是否有吸引力
- 摘要/导语：有没有写，是否概括了文章核心内容
- 封面图：是否已生成、尺寸是否符合要求（承接 kevin-wechat-image 的产出）
- 是否需要原创声明

### 2. 排版适配检查

公众号编辑器对 Markdown 的支持有限，逐项检查文章里有没有这些排版坑：

- 代码块——公众号编辑器经常渲染错乱，建议转成图片或用等宽字体纯文本处理
- 表格——同样容易错位，检查是否需要转图片或改写成列表
- 分割线、引用块——确认转换到公众号编辑器后样式是否还正常
- 超链接——公众号正文默认不支持外链跳转，检查是否需要放进"阅读原文"或用其他方式处理

这份排版坑清单是根据公众号编辑器的通病写的初始猜测，还没拿真实文章验证过。用几次之后如果发现新的坑，或者某条其实不成立，要更新回这个 SKILL.md，不要让清单一直停留在猜测阶段。

### 3. 内容合规检查

- 敏感词/违禁词粗查（如果不确定某个词是否敏感，标注出来让用户自己判断，不要自己删改内容）
- 引用的数据、图片是否需要注明来源
- 是否有需要打码或规避的个人信息、隐私内容

### 4. 汇总检查清单，产出发布就绪文本

给用户一份清单：

```
## 元信息
- [ ] 标题
- [ ] 摘要
- [ ] 封面图
- [ ] 原创声明

## 排版
- [ ] 代码块/表格已处理
- [ ] 外链已处理

## 合规
- [ ] 敏感词粗查
- [ ] 来源标注
```

标记每一项是"通过"还是"需要处理"，需要处理的说明具体问题。全部通过后，把最终文本整理成可以直接粘贴进公众号编辑器的格式。

### 5. 停在这里，交还给用户

到这一步为止。明确告诉用户"检查清单已完成，文本已经是发布就绪状态"，然后停下来——不去点发布、不去调用任何发布接口。真正点发布这个动作，无论清单多干净，都需要用户自己确认和操作。

## 参考示例

```
## 元信息
- [x] 标题（22字，符合要求）
- [ ] 摘要 → 未写，需要补一句话导语
- [x] 封面图
- [x] 原创声明

## 排版
- [ ] 代码块/表格已处理 → 第2节有一个表格，需要转成列表或图片
- [x] 外链已处理

## 合规
- [x] 敏感词粗查
- [x] 来源标注
```

## 边界

- 只做检查和整理，不执行发布动作，不调用发布类 API。
- 不确定是否违规/敏感的内容，标注出来交给用户判断，不擅自删改。
- 清单没通过的项目要明确说清楚问题在哪，不能笼统写"有问题"。
