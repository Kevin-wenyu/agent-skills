# 公众号深度调研

## 这个 skill 做什么

针对已经选定的选题方向，做信息搜集，边搜边把结果存进文件，最后整理成一份结构化简报。不写文章正文，只产出调研素材。

## 执行步骤

### 1. 确认调研范围

如果选题方向、核心角度还不清楚，先跟用户确认要调研的具体问题是什么——不是泛泛地"了解一下这个话题"，而是"这篇文章需要哪几个具体问题的答案"。范围越具体，调研效率越高。

### 2. 按信息源优先级搜索

搜索顺序：

1. 官方信息源——官方博客、官方文档、官方公告
2. 一手报道——权威科技媒体、行业媒体
3. 社区讨论——社交媒体、论坛、评论区，用来补充官方信息里没有的真实反馈和争议点

同一个事实尽量找到至少2个独立信息源交叉验证，只有一个来源的信息在简报里要标注"单一信息源，未交叉验证"。

### 3. 边搜边存，不要等全部搜完再保存

每完成一批搜索（比如搜完"官方信息源"这一类），立刻把结果追加写入调研文件，不要攒到最后一次性写。会话可能中断，增量保存保证已经搜到的东西不会丢。

调研文件建议路径：`research/{选题slug}.md`。

### 4. 汇总成结构化简报

调研文件最终要整理成这个结构：

```
# {选题} 调研简报

## 关键事实
- 事实1（信息源：链接）
- 事实2（信息源：链接，注：单一信息源未交叉验证）

## 信息源列表
- ...

## 待确认问题 / 争议点
- ...
```

### 5. 汇报调研覆盖情况

调研完成后告诉用户：覆盖了哪几类信息源、哪些问题还没找到明确答案、要不要继续深挖某个点。不要默认调研已经"足够"，让用户判断是否可以进入写作。

## 参考示例

```
# GLM-5V-Turbo发布 调研简报

## 关键事实
- 支持128k上下文（信息源：官方博客 https://...）
- 定价较上一代下降40%（信息源：官方公告 https://...，注：单一信息源未交叉验证）

## 信息源列表
- 官方博客：https://...
- 科技媒体报道：https://...

## 待确认问题 / 争议点
- 是否支持流式多模态输入，官方文档表述模糊，实测前无法确认
```

## 边界

- 不写文章正文，只产出调研素材文件。
- 单一信息源的事实必须标注清楚，不能当作已验证的定论呈现。
- 找不到足够信息时，在简报里如实写"信息不足"，不要编造内容填充。
