# 公众号三遍审校

## 这个 skill 做什么

对已经写完的初稿做三遍审校，每遍聚焦不同维度，每条问题都带修改建议。不是通读一遍挑几个错别字，而是系统性地过三遍。

## 为什么分三遍

一次性检查所有维度，AI会顾此失彼，重要问题被细枝末节淹没。分三遍、每遍只盯一件事，准确率明显更高。

## 执行步骤

### 第一遍：查事实

逐句核对文章里的事实性陈述：日期、数字、人名、产品名、引用的数据来源。有调研简报的话，对照调研文件核实；没有的话，标记出"这句需要核实来源"。

事实错误优先级最高——一篇文章语言再优美，发布日期写错了也是废品。这一遍找到的问题必须先改完，再进入下一遍。

### 第二遍：降 AI 味

检查以下几类具体问题（这份清单需要随实际写作习惯持续更新，不是一次定死）：

- 套话词汇：说白了、简单来说、换句话说、不可否认、毫无疑问、值得注意的是——直接删除或替换成具体表达
- 句式模式：排比式总结（"不仅...而且...更..."）、过度使用"这不仅仅是...更是..."这类升华句
- 标点习惯：破折号全篇控制在1-2处以内；「」引号不过度使用
- 结构痕迹：每段都是"观点+例子+总结"的机械三段式

每处标记都要给出具体的改写版本，不能只说"这里AI味重"。

### 第三遍：打磨细节

标题是否有吸引力、开头三句话能不能留住读者、段落长度是否适合手机阅读（单段不超过4-5行）、有没有可以删掉的冗余句子。

## 审校报告格式

三遍都做完后，给用户一份汇总：

```
## 第一遍·事实核查
- [位置] 问题 → 建议

## 第二遍·AI味
- [位置] 问题 → 建议

## 第三遍·细节
- [位置] 问题 → 建议
```

## 参考示例

```
## 第二遍·AI味
- [第3段第1句] "说白了，这个功能就是让AI记住你的习惯。" → 删掉"说白了"，直接说"这个功能让AI记住你的习惯。"
- [第5段] 整段是"观点+例子+总结"机械三段式，读起来像模板 → 删掉总结句，让例子本身说话
```

## 边界

- 只提出修改建议，不擅自替用户改定稿——除非用户明确说"直接改"。
- 事实核查发现无法确认的内容，标注"待核实"，不要自行编造或删除。
- 这份清单是起点，用几次之后如果发现某类问题反复出现但清单没覆盖到，应该更新这个 SKILL.md 本身。
