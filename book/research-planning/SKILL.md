# 调研与规划（技术书籍写作流水线 · 第1/5阶段）

## 这个 skill 做什么

把一个模糊的"我要写一本书"想法，变成一份确认过的 `PROJECT.md`（书名、目标读者、章节列表、每章一句话简介、状态）加每章一份调研笔记文件。产出是后续"内容写作"阶段的直接输入。本 skill 不写正文。

## 前置：这是流水线的一环

技术书籍写作5阶段流水线：调研与规划 → 内容写作 → 构建与组装 → 版本管理 → 多格式输出。本 skill 只做第1阶段，做完后把状态和产出文件整理清楚，交给下一阶段接手。

## 执行步骤

### 1. 先问清楚范围，不要跳过

开始搜索之前，向用户确认：

- 书的主题、目标读者（初学者还是有经验的开发者）
- 大致篇幅/章节数量预期（用户没想法就给一个参考区间，比如8-12章）
- 有没有已经想好的部分大纲或参考书目
- 语气风格（严谨教程 / 轻松实战 / 夹叙夹议）

如果这些信息之前的对话里已经给过，不用重复问，直接进入下一步。

### 2. 提出2-3个章节结构方案，不要替用户定一个

基于主题生成2-3个不同方向的章节结构（例如：按技术栈层层深入 / 按项目实战串联 / 按问题场景分类）。每个方案要包含：

- 章节列表（标题 + 一句话简介）
- 这个结构的优势
- 这个结构的代价或风险（比如"部分章节依赖前置知识，读者跳读体验差"）

摆出方案等用户选或要求调整，不要自己拍板。

### 3. 确认结构后，逐章调研，边做边存

对每一章：

1. 搜索信息源，优先官方文档、GitHub、技术博客、Release Notes，其次才是二手转述
2. 每完成一章调研，立刻写入 `research/chapter-{编号}-{slug}.md`，不要等全部章节搜完再一次性保存——会话可能中断，增量存档保证已完成部分不丢
3. 每份调研笔记包含：关键事实、信息源链接、待确认的问题或矛盾点

调研笔记是原始素材，不是成稿，不用打磨文笔。

### 4. 汇总 PROJECT.md

所有章节调研完成后（或用户中途要求停止），生成/更新 `PROJECT.md`：

```
# {书名}

## 目标读者
...

## 章节结构
| # | 标题 | 一句话简介 | 状态 | 调研文件 |
|---|------|-----------|------|---------|
| 1 | ...  | ...       | 已调研 | research/chapter-1-xxx.md |
```

状态字段用：未开始 / 调研中 / 已调研 / 写作中 / 已完稿，方便下一阶段的 skill 判断从哪里接手。

### 5. 汇报并确认，再收尾

向用户展示 `PROJECT.md` 摘要和已生成的调研文件列表，明确问："这个结构和调研深度可以进入内容写作阶段了吗，还是有章节需要调整或深挖？"得到确认后再结束本 skill 的执行。

## 参考示例

假设主题是"给后端工程师讲AI Agent工程化"，其中一个章节结构方案示例：

```
方案2：按项目实战串联
| # | 标题 | 一句话简介 |
|---|------|-----------|
| 1 | 从一个命令行工具开始 | 用最小可行的Agent跑通"输入→工具调用→输出"闭环 |
| 2 | 加上记忆 | 接入向量数据库，让Agent能处理长对话 |
| 3 | 加上并行 | 拆分子任务，多个Agent协作完成一个大任务 |

优势：每章都有可运行的产出，读者跟着敲代码就有成就感
风险：项目难度爬升曲线不好把控，中间某一章太难，后面读者可能直接放弃
```

## 边界

- 不写正文，只做规划和调研素材收集。
- 不假设章节数量或结构，必须让用户确认。
- 单章信息源少于3个时，在调研笔记里明确标注"信息不足，建议进一步调研"，不要编造内容填充。
