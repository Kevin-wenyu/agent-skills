# 公众号配图

## 这个 skill 做什么

给一篇文章配图：先提方向选，再生成上传，最后质检。不是拿到需求直接甩一张图出来。

## 首次使用要确认的信息（确认后应写回本文件，以后不用再问）

- 用什么生图工具/API（比如 Midjourney、DALL·E、即梦、Stable Diffusion 等）
- 用什么图床/存储服务拿永久链接
- 审美偏好和禁忌风格（比如不用某种色调、不要某种构图、封面要不要加水印）

如果这些还没定过，先问用户，问完之后把答案更新进本文件的这一节，下次直接用，不用重复问。**必须是用户明确回答之后才写入**——不能把示例工具名或猜测的偏好当成已确认配置填进来，没问清楚就先按"待确认"处理，宁可多问一次也不要埋一个错误配置进去。

## 执行步骤

### 1. 提3个配图方向，等用户选

根据文章内容，给3个方向，每个方向说清楚：

- 类型（概念图 / 信息图 / 氛围图 / 场景插画等）
- 大致构图和风格描述
- 适合放在文章的哪个位置（封面 / 小节配图）

不要自己选一个直接生成，等用户确认方向。

### 2. 调用生图工具生成，上传图床

- API 密钥从环境变量读取，不要硬编码在对话或文件里
- 生成图片 → 上传图床拿到永久链接 → 把 Markdown 图片链接内联到文章对应位置
- 每一步都要有反馈："正在生成...生成完成，正在上传...上传成功，链接：https://..."。生图和上传都是可能失败的操作，用户需要知道进度和结果，不能悄无声息地失败。
- 如果生成结果不满意，重新生成，不要将就着用。

### 3. 质量检查清单

图片生成并内联后，逐项检查：

- 有没有文字畸变（AI生图经常把图里的文字生成得乱七八糟）
- 有没有踩到审美禁忌（参考上面记录的偏好）
- 封面有没有多余的水印/logo
- 分辨率是否够用（公众号封面图有最低尺寸要求）
- 文章里的图片链接是否都能正常访问，没有 placeholder

有问题的直接标出来并重新生成，不要留着"大概能用"的图。

## 参考示例

```
方向1：信息图
- 构图：左右对比布局，左边"以前"右边"现在"
- 风格：浅色背景、单色系配色
- 位置：封面图

方向2：概念图
- 构图：中心图标 + 周围4个关联要素辐射
- 风格：线条插画风
- 位置：文章中段配图
```

## 边界

- 生图和图床的密钥永远从环境变量读取，不写进 SKILL.md 或对话记录。
- 不跳过方向选择直接生成——即使只有一个显而易见的方向，也要说清楚"这是唯一合理方向，原因是..."，而不是默认执行。
- 最终产出里不允许有 placeholder 图片链接，所有链接必须是真实可访问的。
